### 1. Robustez técnica — validación de stock en tiempo real (POS)

**Archivo:** `app/punto-de-venta/page.tsx`

Antes de procesar cualquier cobro, el POS ahora verifica el stock actual en Supabase en lugar de confiar en el estado local. Si algún producto no tiene suficiente stock, se muestra un error y se cancela la operación.

```ts
const { data: stockActual } = await supabase
  .from('productos').select('id, stock, nombre').in('id', ids)
// Verifica cada ítem del carrito contra el stock real
```

### 8. Fix de tipos TypeScript para build en Vercel

**Archivos:** `app/dashboard/page.tsx`

Tres errores de tipo causados por anotaciones explícitas en callbacks de `.forEach()` que Supabase infería diferente:

- `items.forEach((i: {...}) =>` → cambiado a `items.forEach((i) =>`
- `i.productos` casteado con `as unknown as { categorias: ... } | null`
- `clientesGasto.forEach((v: {...}) =>` → cambiado a `clientesGasto.forEach((v) =>`  con cast interno

### 9. Fix: path de imagen inválido en Android (Supabase Storage)

**Archivo:** `app/productos/page.tsx`

El SKU se usaba directamente como nombre de archivo en Storage. En Android, los SKUs con espacios, tildes o caracteres especiales causaban `Invalid path specified in request URL`.

```ts
const safeSku = form.sku.trim().toLowerCase().replace(/[^a-z0-9-_]/g, '-')
const path = `${Date.now()}-${safeSku || 'producto'}.webp`
```

### 17. Auditoría completa del schema SQL

Se cruzó el archivo `schema.sql` contra el código para detectar inconsistencias. Hallazgos:

- **Bug crítico:** `trg_descontar_stock` y `trg_actualizar_tag` solo eran `AFTER UPDATE` — el POS inserta con `estado='Pagado'` directamente (INSERT) por lo que los triggers nunca disparaban. Stock no bajaba y tag del cliente no cambiaba en ventas POS.
- **Seguridad:** `config_storefront` tenía políticas RLS pero RLS no estaba habilitado en la tabla.
- **Tablas faltantes:** `config_notificaciones`, `config_metodos_pago`, `cart_items`.
- **Columnas faltantes:** `updated_at` en `registros` y `solicitudes_productos`; `telefono` y `facebook` en `config_storefront`; dirección completa en `clientes`.
