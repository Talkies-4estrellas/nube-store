### [10:05] Commit: cambios

**Hash:** `d248eb1`

**Archivos modificados:**
| Archivo | Cambio |
|---------|--------|
| `lib/supabase.ts` | Valida `NEXT_PUBLIC_SUPABASE_URL` con `new URL()` antes de instanciar el cliente; limpia comillas/espacios; cae al mock con `console.error` explícito si la variable falta o es inválida en vez de romper el build |
| `lib/supabase-server.ts` | Misma validación para el cliente de servidor (service role) |

**Descripción:**
El deploy en Vercel fallaba con `Error: Invalid supabaseUrl: Must be a valid HTTP or HTTPS URL` durante el prerenderizado de `/_not-found`. La causa: la variable de entorno se había pegado en Vercel con el nombre incluido (`NEXT_PUBLIC_SUPABASE_URL=https://...` en vez de solo el valor). Se agregó una función `urlValida()` que valida con el constructor `URL()` nativo antes de pasarle la cadena a `createBrowserClient`. Si la URL es inválida, el build ya no truena — el cliente cae al mock (que ya existía para builds sin variables) y se imprime un mensaje claro indicando qué falta corregir.

También se diagnosticó por separado (sin cambios de código) que el catálogo vacío en producción venía de dos causas distintas: (1) las variables `NEXT_PUBLIC_*` se incrustan en el bundle al momento del **build**, así que agregarlas en Vercel sin volver a desplegar no tiene efecto; (2) la URL de la Project API (`Settings → API`) es distinta de la que muestra la pantalla *Data API* del dashboard (esa trae `/rest/v1/` al final, que el SDK ya agrega solo).

**Descripción:**
Arranca la auditoría de responsividad: en vez de revisar a ojo, se inyectó un script en el navegador que compara `document.documentElement.scrollWidth` contra `clientWidth` a 375px de ancho en cada pantalla del panel, identificando exactamente qué elemento se desborda y por cuánto. La causa raíz más común: `1fr` en CSS Grid equivale a `minmax(auto, 1fr)`, y ese `auto` impide que una columna se encoja por debajo del tamaño de su contenido — por eso `.stat-grid` y `.grid-3` mostraban columnas de ~294px dentro de contenedores de 343px. Se corrigió a `minmax(0, 1fr)` en todos los grids afectados.

Paralelamente se armó el flujo para exportar los datos de la base de datos vieja de Supabase (`arqoyuxcugpprzjpcytg`) hacia la cuenta nueva (`vzpewbaipftsocbauehe`), ya que no existía ningún respaldo real de los datos en el repositorio — solo el esquema. El script genera INSERTs (no `COPY`) para poder pegarlos directo en el SQL Editor sin necesitar `psql` instalado.
